# Объектно-ориентированное программирование в Python

## Базовые принципы ООП
* Инкапсуляция — размещение одного объекта или класса внутри другого для разграничения доступа к ним
* Наследование — способность объекта или класса базироваться на другом объекте или классе. Это главный механизм для повторного использования кода. Наследственное отношение классов четко определяет их иерархию
* Полиморфизм — реализация задач одной и той же идеи разными способами
* Абстракция — отделение концепции от ее экземпляра

### Инкапсуляция

Инкапсуляция есть объединение в единое целое данных и алгоритмов обработки этих данных. В рамках ООП данные называются полями объекта, а алгоритмы - объектными методами.

Инкапсуляция позволяет в максимальной степени изолировать объект от внешнего окружения. Она существенно повышает надежность разрабатываемых программ, т.к. локализованные в объекте алгоритмы обмениваются с программой сравнительно небольшими объемами данных, причем количество и тип этих данных обычно тщательно контролируются. В результате замена или модификация алгоритмов и данных, инкапсулированных в объект, как правило, не влечет за собой плохо прослеживаемых последствий для программы в целом (в целях повышения защищенности программ в ООП почти не используются глобальные переменные).

### Наследование

Наследование есть свойство объектов порождать своих потомков. Объект-потомок автоматически наследует от родителя все поля и методы, может дополнять объекты новыми полями и заменять (перекрывать) методы родителя или дополнять их.

Принцип наследования решает проблему модификации свойств объекта и придает ООП в целом исключительную гибкость. При работе с объектами программист обычно подбирает объект, наиболее близкий по своим свойствам для решения конкретной задачи, и создает одного или нескольких потомков от него, которые «умеют» делать то, что не реализовано в родителе.

Последовательное проведение в жизнь принципа «наследуй и изменяй» хорошо согласуется с поэтапным подходом к разработке крупных программных проектов и во многом стимулирует такой подход.

### Полиморфизм

Полиморфизм - это свойство родственных объектов (т.е. объектов, имеющих одного общего родителя) решать схожие по смыслу проблемы разными способами. В рамках ООП поведенческие свойства объекта определяются набором входящих в него методов. Изменяя алгоритм того или иного метода в потомках объекта, программист может придавать этим потомкам отсутствующие у родителя специфические свойства. Для изменения метода необходимо перекрыть его в потомке, т.е. объявить в потомке одноименный метод и реализовать в нем нужные действия. В результате в объекте-родителе и объекте-потомке будут действовать два одноименных метода, имеющие разную алгоритмическую основу и, следовательно, придающие объектам разные свойства.

### Абстракция

Абстракция в объектно-ориентированном программировании — это использование только тех характеристик объекта, которые с достаточной точностью представляют его в данной системе. Основная идея состоит в том, чтобы представить объект минимальным набором полей и методов и при этом с достаточной точностью для решаемой задачи.

Абстракция является основой объектно-ориентированного программирования и позволяет работать с объектами, не вдаваясь в особенности их реализации.

class Apple(Fruit, Food):
    def __init__(self, ripe, count=1, max_count=32, color='green', saturation=10):
        super().__init__(saturation=saturation, ripe=ripe, count=count, max_count=max_count)
        self._color = color

    @property
    def color(self):
        return self._color

    @property
    def eatable(self):
        return super().eatable and self._ripe

    def __call__(self):
        """ Вызов как функции """
        if self.eatable:
            new_count = max(self.count - 1, 0)
            self.update_count(new_count)

    def __str__(self):
        """ Вызов как строки """
        return f'Stack of {self.count} {self.color} apples'

    def __len__(self):
        """ Получение длины объекта """
        return self.count

### Имитация списка

```python
class MultLists:
    def __init__(self, lst1, lst2):
        self._lst1 = lst1
        self._lst2 = lst2

    def __getitem__(self, index):
        """ Получение элемента по индексу """
        if index > len(self):
            raise IndexError(f'Index {index} more then {len(self)}')
        return self._lst1[index], self._lst2[index]

    def __len__(self):
        return min(len(self._lst1), len(self._lst2))
```

Что такое декоратор в Python?
В Python «декоратор» — это функция, которая:
-принимает другую функцию (или метод) как аргумент;
-возвращает новую функцию, обычно вызывающую исходную плюс добавляющую какую‑то дополнительную логику (логирование, проверки, кеш и т.п.).

Синтаксис с @ — это просто удобный способ применить декоратор к функции.



Синтаксис
```python
@decorator
def func(...):
    ...
```

Эквивалнтен  
```python
def func(...):
    ...
func = decorator(func)
```python

# Декоратор для метода класса 
def method_logger(method):
    """Декоратор для метода класса: печатает имя метода и имя объекта"""
    def wrapper(self, *args, **kwargs):
        print(f"Вызов метода {method.__name__} для {self.name}")
        return method(self, *args, **kwargs)
    return wrapper

class Person:

    def say(self, message):

# Еще пример: декоратор для замера времени выполнения функции
import time
def timer(func):
    def wrapper(*args, **kwargs):

        result = func(*args, **kwargs)

# 1) Простой декоратор (без параметров)

def simple_trace(func):
    """Печатает вход и выход из функции."""
    @functools.wraps(func)  # сохраняем метаданные func (имя, docstring) в wrapper
    def wrapper(*args, **kwargs):
        print(f"[TRACE] start {func.__name__}")
        result = func(*args, **kwargs)
        print(f"[TRACE] end {func.__name__}")
        return result
    return wrapper

# Пример использования simple_trace
@simple_trace
def cut_fruit(name):
    return f"Нарезаем: {name}"

print(cut_fruit("apple"))  # сразу видим работу декоратора

def log_with_time(prefix):
    """Декоратор с параметром: добавляет в лог время и префикс."""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            now = datetime.datetime.now().strftime("%H:%M:%S")
            print(f"[{now}] {prefix}: {func.__name__}")
            return func(*args, **kwargs)
        return wrapper
    return decorator

# Пример использования log_with_time
@log_with_time("INFO")
def prepare_fruit(name):
    print(f"Готовим {name}")

prepare_fruit("banana")  # вызов с декоратором

# --------------------------------------------------------------------
# 3) Абстрактный базовый класс (ABC) — задаёт обязательные методы
#    Критически важно: наследники обязаны реализовать все абстрактные методы,
#    иначе нельзя создать экземпляр.
# --------------------------------------------------------------------

class Eatable(ABC):
    """Абстрактный класс для съедобных объектов.
    Все наследники обязаны реализовать is_eatable и calories.
    """

    @abstractmethod
    def is_eatable(self) -> bool:
        """Можно ли есть?"""
        pass

    @abstractmethod
    def calories(self) -> int:
        """Сколько килокалорий?"""
        pass

# Попытка создать класс, не реализующий абстрактные методы, вызовет ошибку
class BadFruit(Eatable):
    pass

try:
    apple = BadFruit()  # TypeError
except TypeError as e:
    print(f"Ошибка (ожидаемо): {e}")

# Правильная реализация
class Apple(Eatable):
    def is_eatable(self):
        return True
    def calories(self):
        return 52

good_apple = Apple()
print(f"Яблоко съедобно? {good_apple.is_eatable()}, калорий: {good_apple.calories()}")
print()
```

class Fruit(Eatable):
    """Базовый фрукт с именем, калориями и состоянием свежести."""
    def __init__(self, name, cal, freshness):
        self._name = name
        self._cal = cal
        self.fresh = freshness      # композиция

    @property
    def name(self):
        return self._name

    def is_eatable(self):
        return self.fresh.is_fresh()

    def calories(self):
        return self._cal

    @log_with_time("INFO")          # применяем декоратор с параметром
    def scout(self):
        print(f"{self.name}: {self.fresh.days} дней свежести")

    def __str__(self):
        return f"{self.name} (свежее? {self.is_eatable()}, {self.calories()} ккал)"

# Создаём и используем Fruit

basic_fruit.scout()
print(basic_fruit)
print()

# --------------------------------------------------------------------
# 7) Декоратор проверки свежести (require_fresh)
#    Критически важно: этот декоратор применяется к методам, которые должны
#    выполняться только для свежих фруктов.
# --------------------------------------------------------------------

def require_fresh(func):
    """Декоратор для методов, которые можно вызывать только у свежих фруктов."""
    @functools.wraps(func)
    def wrapper(self, *args, **kwargs):
        if not self.is_eatable():
            print(f"{self.name}: несвежее, есть нельзя!")
            return None
        return func(self, *args, **kwargs)
    return wrapper

# Теперь создадим класс, использующий этот декоратор
class FreshApple(Apple):
    @require_fresh
    @log_with_time("EAT")
    def eat(self):
        return f"Съели {self.name} ({self.calories()} ккал)"

fresh_apple = FreshApple(Freshness(1), "fuji")
old_apple = FreshApple(Freshness(6))

print(fresh_apple.eat())   # свежее — можно съесть
print(old_apple.eat())     # несвежее — отказ
print()
```

# --------------------------------------------------------------------
# 8) Статические методы и методы класса (@staticmethod, @classmethod)
#    '@staticmethod' — метод, не привязанный ни к экземпляру, ни к классу.
#    '@classmethod' — метод, получающий класс вместо self, часто используется как фабрика.
# --------------------------------------------------------------------

class FruitUtils:
    """Класс для демонстрации статических методов и методов класса."""

    @staticmethod
    def is_fruit(name):
        """Проверяет, является ли строка названием фрукта."""
        return name.lower() in {"apple", "banana", "orange"}

    @classmethod
    def create_fresh_fruit(cls, name, cal=50):
        """Фабричный метод: создаёт фрукт со свежестью 1 день."""
        # Здесь cls — это класс, который вызвал метод (может быть подклассом)
        return Fruit(name, cal, Freshness(1))

print("Картошка — фрукт?", FruitUtils.is_fruit("potato"))
